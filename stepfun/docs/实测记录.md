# 实测记录

> 本节数据来自提交应用在真实设备上的运行结果，原始 JSON 由页面「导出实测 JSON」生成（见 `records/benchmark-q8-webgpu.json`）。

## 1. 测试环境

- **设备**：AMD Ryzen 9 8945HX（16 核 32 线程）· 核显 AMD Radeon 610M（WebGPU 后端）· 32 GB 内存（Windows 11，WSL2 运行 seekdb）
- **浏览器**：Microsoft Edge 157（Chromium 157，WebGPU 可用）
- **端侧模型**：`Xenova/paraphrase-multilingual-MiniLM-L12-v2`（多语言，384 维），INT8 动态量化（q8），模型体积 **112.8 MB**，随项目本地分发（`web/models/`），推理全程在浏览器内完成，无任何云端推理接口调用
- **存储与检索**：`@oceanbase/seekdb-node`（嵌入式，WSL2 Ubuntu 22.04，Node v22.23.4），表 `kb_chunks`，向量列 `VECTOR(384)` + HNSW 索引（cosine），全文索引使用 **ik 中文解析器**；混合检索为**单条 SQL**（`MATCH ... AGAINST` 过滤 + `l2_distance ... APPROXIMATE` 排序），前端不做两路结果拼合
- **语料与查询集**：8 篇示例文档 / 8 个分块（`data/corpus.json`），评测集 8 条中文查询（`data/queries.json`，含相关性标注）

## 2. 分阶段耗时（INT8 (q8) + WebGPU）

| 阶段 | 耗时 | 备注 |
| --- | --- | --- |
| 模型下载与加载 | 3.30 s | 首次下载 112.8 MB（本地静态分发，无外网依赖） |
| 预热推理 | 1.20 s | 首帧编译（冷启动与热启动分离开计） |
| 文档向量化 | 1.77 s | 8 块 · batch=8 · ≈4.5 块/秒 |
| 写入 seekdb | 319.7 ms | 插入 8 块（单一 INSERT，事务批量） |
| 索引确认 | 14.8 ms | 增量索引即时可见，无需重建 |
| 查询向量化 | 224.0 ms | 单条 · 首次编译（热路径显著更快） |
| seekdb 检索 | 107.1 ms | mode=hybrid · top 5（单条 SQL） |
| 端到端（提交→展示） | 343.5 ms | 含一次一端提示 |
| **评测平均检索延迟** | **18 ms** | q8 / WebGPU 热路径 |

> FP32 / FP16 基线可通过页面精度下拉框（INT8 / fp16 / fp32）切换后按同一流程复测；本文以默认交付配置（q8）实测为准。

## 4. 结论

1. **量化收益**：INT8 (q8) 将多语言 MiniLM-L12 模型压到 112.8 MB（约为 FP32 的 1/4），首次加载 3.3 s、热路径单条检索 18 ms，端侧推理在核显（WebGPU）上即可获得交互级延迟。
2. **质量代价可控**：q8 下 Recall@5 = 0.6875 / nDCG@5 = 0.5077；如需更高质量基线，页面可直接切换 fp32 复测（同一评测集）。
3. **降级路径可用**：WebGPU 初始化失败时自动降级 WASM 并在顶部徽标明示；后端 seekdb 走 unix socket / TCP 自适应连接，`fts=ik` 中文解析器自动探测建表。
4. **全链路无云端依赖**：模型、onnx 运行时（wasm）均随项目本地分发（`web/models/`、`web/vendor/`），断网可完整复跑。
