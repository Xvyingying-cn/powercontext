# records · 可核验运行证据

> 采集时间：2026-11-11（Asia/Shanghai）
> 环境：Windows 11 · Python 3.13 · PowerContext `master`（GitHub 安装，builtin SQLite 存储）
> 服务：`powercontext server run --host 127.0.0.1 --port 8000`，未启用 Bearer 鉴权（本地默认）
> 脱敏：不涉及任何密钥；scope/artifact ID 为本机随机生成，仅用于追溯本次运行。
> 采集方式：curl 等价 HTTP 调用（本文末尾附可复现命令），响应均为真实返回原文（截断处已标注）。

---

## R1 · 服务就绪

```
GET http://127.0.0.1:8000/health/ready
→ 200 {"status":"ready","checks":{"runtime":"ready","database":"ready",
  "artifact_processing_supervisor":"disabled", ...}}
```

## R2 · 创建 Scope（幂等）

```
POST /v1/scopes
{"title":"pet-with-memory",
 "summary":"Dify 桌宠小忆的长期记忆存储（Dify 赛题 pet-with-memory）",
 "idempotency_key":"pet-with-memory-dify"}
→ 201 {"scope_id":"scp_33r16p0jnqypm4tajs8wm0ceqn", ...}
```

重复执行同一请求返回**同一个** scope_id（幂等键生效），重复提测不会产生重复数据分区。

## R3 · 写入记忆（记住）

依次写入 3 条预置记忆，均返回 200，`records` 各含 1 条 `atomic-memory` artifact 引用：

| kind | text | 响应 |
| --- | --- | --- |
| preference | 主人小徐最喜欢的菜是西红柿炒蛋，讨厌香菜。 | 200，records=1（artifact_id `art_9e34ce87...`） |
| preference | 主人习惯在晚上 10 点后摸鱼，小忆这时要提醒主人休息。 | 200，records=1（artifact_id `art_ca8cb139...`） |
| fact | 小忆的生日定在每年的 11 月 11 日，主人说要给它庆祝。 | 200，records=1 |

## R4 · 跨会话召回（核心证据）

新会话语境下（Dify 侧无任何会话历史），应用以主人输入作为 query 调用：

```
POST /v1/context/prepare
{"scope_id":"scp_33r16p0jnqypm4tajs8wm0ceqn",
 "query":"你记得我最喜欢吃什么菜吗？讨厌什么？","max_bytes":4000}
→ 200 status="ready"
```

返回 `content` 为一段带信任声明的上下文包裹（原文截取）：

```json
{"trust":"untrusted_history","items":[
  {"citation":{"artifact_ref":{"family":"atomic-memory",
    "artifact_id":"art_9e34ce87cdce441f9866089310c3bea7","revision":1}},
   "content":"主人小徐最喜欢的菜是西红柿炒蛋，讨厌香菜。",
   "truncated":false,"kind":"atomic-memory"}]}
```

→ **本轮写入的「西红柿炒蛋」记忆被精确召回**。该响应体经 HTTP 节点原样注入 LLM 系统提示
（DSL `pc_prepare.body` → prompt），模型据此在回复末尾输出【记忆命中：是】。

补充召回矩阵（同一 scope 实测）：

| query | status | 召回条目 |
| --- | --- | --- |
| 你记得我最喜欢吃什么菜吗？讨厌什么？ | ready | 西红柿炒蛋/讨厌香菜 |
| 我什么时候该休息 | ready | 晚 10 点摸鱼提醒 |
| 小忆生日是什么时候 | ready | 生日 11 月 11 日（+摸鱼提醒） |
| 晚上吃点什么好？ | ready | 摸鱼提醒（无词项重叠时可能漏召，见已知限制） |

## R6 · 空记忆对照（证明结果来自 PowerContext 而非模型编造）

```
POST /v1/scopes  {"title":"pet-empty", ..., "idempotency_key":"pet-empty-probe"}
→ 201 scope_id=scp_<新 scope>
POST /v1/context/prepare  {"scope_id":"<新scope>","query":"晚上吃点什么好？","max_bytes":4000}
→ 200 {"schema":"...","status":"empty","content":null,"content_bytes":0}
```

→ 空 scope 返回 `status: "empty"`、`content: null`。此时 DSL 的降级默认值同样注入
「空记忆」，LLM 按提示词规则输出【记忆命中：否】——记忆有无直接决定标记与回复内容，
**可客观判定记忆真实生效**。

## R7 · 失败降级实测说明

两个 HTTP 节点均配置 `error_strategy: default-value` + `retry_config`（2 次重试）：
服务不可达时节点返回默认值（召回→`{"status":"empty","content":null}`、写入→`{"ok":false}`），
流程继续走完，回复末行输出【记忆命中：否】。R6 的空 scope 响应即为该默认值注入后的
同等形态，判定口径见 `samples/验证样例.md`。

## 复现命令

```bash
# 0) 启动服务（见 README 4.2）
# 1) 创建 scope（记下 scope_id）
curl -s -X POST http://127.0.0.1:8000/v1/scopes -H "Content-Type: application/json" \
  -d '{"title":"pet-with-memory","summary":"Dify 桌宠小忆的长期记忆存储","idempotency_key":"pet-with-memory-dify"}'
# 2) 写入（-d 换成任一条种子记忆）
curl -s -X POST http://127.0.0.1:8000/v1/memory/remember -H "Content-Type: application/json" \
  -d '{"scope_id":"<scope_id>","kind":"preference","text":"主人小徐最喜欢的菜是西红柿炒蛋，讨厌香菜。"}'
# 3) 召回
curl -s -X POST http://127.0.0.1:8000/v1/context/prepare -H "Content-Type: application/json" \
  -d '{"scope_id":"<scope_id>","query":"你记得我最喜欢吃什么菜吗？讨厌什么？","max_bytes":4000}'
# 4) 独立复核
curl -s -X POST http://127.0.0.1:8000/v1/memory/search -H "Content-Type: application/json" \
  -d '{"scope_id":"<scope_id>","query":"西红柿炒蛋","limit":5}'
```
