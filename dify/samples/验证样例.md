# 验证样例 · pet-with-memory（samples）

判定核心只有一个：**换一个新会话，小忆是否还记得上一个会话说过的具体事实**。

三个样例依次是：`埋记忆（新会话）→ 新会话召回（核心）→ 空 Scope 对照`。
每个样例的预期表现均对应「声明规则」：回复末行必有【记忆命中：是/否】客观标记，
记忆的有无直接决定标记取值与回复内容。

---

## 前置（从零到可体验，约 10 分钟）

```bash
# 1) 启动 PowerContext（默认 127.0.0.1:8000，无鉴权），详见 README 4.2
# 2) 创建 Scope 并预置示例记忆
cd dify/scripts && python init-scope.py --seed
#    末行输出 SCOPE_ID=scp_xxx，复制它
# 3) 导入 dify/app.dsl.yml（Dify 控制台 → 导入 DSL 文件）
# 4) 应用「环境变量」里设置两项后发布：
#    POWERCONTEXT_BASE_URL = http://127.0.0.1:8000   （Dify 与 PowerContext 同机时的默认值）
#    PC_SCOPE_ID           = 上一步的 SCOPE_ID
# 5) 右上角「访问 API」创建 Service API Key
```

统一调用器（把回答、会话 ID、token 一起打出来，便于判定）：

```bash
KEY=app-<your-app-key>            # 控制台创建的 Service API Key
API=http://<dify-host>/v1/chat-messages
USER=demo-user

ask() {  # $1=query  $2=conversation_id(可空；留空即新会话)
  python3 - "$1" "$2" > /tmp/req.json <<'PY'
import json,sys,os
b={"inputs":{},"query":sys.argv[1],"response_mode":"blocking","user":os.environ.get("USER","demo-user")}
if sys.argv[2]: b["conversation_id"]=sys.argv[2]
print(json.dumps(b,ensure_ascii=False))
PY
  curl -s --max-time 240 -X POST "$API" -H "Authorization: Bearer $KEY" \
    -H 'Content-Type: application/json' --data @/tmp/req.json \
  | python3 -c "
import sys,json
d=json.load(sys.stdin)
if d.get('code'): print('ERROR',d); raise SystemExit
print('ANSWER:',d.get('answer'))
print('CID   :',d.get('conversation_id'))
print('TOKENS:',((d.get('metadata') or {}).get('usage') or {}).get('total_tokens'))
"
}
```

> 不想用 API 的话，在 Dify 聊天界面直接输入同样的话、点「新对话」按钮即新会话，判定方式相同。

## 样例 1 ｜埋记忆（新会话）

**初始条件**：`PC_SCOPE_ID` 指向的 Scope 已按前置步骤预置 3 条记忆
（西红柿炒蛋 / 晚 10 点摸鱼提醒 / 生日 11 月 11 日）。

**输入**：

```bash
ask '我叫小徐，最喜欢吃西红柿炒蛋，讨厌香菜' ''
```

**预期**：
- 小忆软萌回应并表示记住了；
- 结尾含【记忆命中：是】（预置记忆已含该条，召回命中）；
- `TOKENS > 0`（LLM 真实出词）。

**核对点**：编排页打开本轮运行详情，「PowerContext 写入记忆」HTTP 节点
`POST /v1/memory/remember` 返回 200、`records` 含 1 条 atomic-memory 引用
（真实响应样例见 `records/运行证据.md` R3）。

**判定口径**：回答自然 + 末行【记忆命中：是】+ remember 节点 200 → 通过。

## 样例 2 ｜新会话召回（核心证据）

**初始条件**：`USER` 与样例 1 相同；**`conversation_id` 留空**（全新会话，Dify 侧无任何历史上下文）。

**输入**：

```bash
ask '你记得我最喜欢吃什么菜吗？' ''
```

**预期**：
- 回答中出现**西红柿炒蛋**（可自然带出讨厌香菜）；
- 结尾含【记忆命中：是】；
- 返回的 `CID` 与样例 1 **不同**（证明不是会话历史起作用）。

**核对点**：「PowerContext 召回记忆」HTTP 节点 `POST /v1/context/prepare` 返回
`status: ready`，`content` 中包含 `主人小徐最喜欢的菜是西红柿炒蛋，讨厌香菜。`
（真实响应样例见 `records/运行证据.md` R4）。

**判定口径**：新会话（CID 不同）+ 回答含西红柿炒蛋 + 末行【记忆命中：是】→ 通过。

## 样例 3 ｜空 Scope 对照（隔离性）

**初始条件**：把应用环境变量 `PC_SCOPE_ID` 改为一个**全新的空 scope**
（`python scripts/init-scope.py --url ...` 不加 `--seed` 新建一个，或直接改 `PC_SCOPE_ID` 为任意未初始化的值）。

**输入**：

```bash
ask '你记得我最喜欢吃什么菜吗？' ''
```

**预期**：
- 回答是热情的"初次见面"式打招呼，**不出现**西红柿炒蛋；
- 结尾含【记忆命中：否】。

**核对点**：prepare 节点返回 `status: "empty"`、`content: null`
（真实响应样例见 `records/运行证据.md` R6）。

**判定口径**：不出现记忆内容 + 【记忆命中：否】→ 通过。
（说明：证明回复内容由 PowerContext 记忆状态决定，而非模型编造。）

导入 `pet-with-memory.yml`，配置与主应用相同的两个环境变量并绑定模型：

| 输入 `主人想对小忆说的话` | 预期输出 |

| 最近工作好忙，没时间陪小忆玩 | Markdown 报告，`## 💾 记忆里的小忆` 一节出现预置记忆内容（西红柿炒蛋 / 摸鱼提醒 / 生日），`## 🍚 今日建议` 把建议与记忆条目对应 |
| （换空 Scope 再跑） | 报告明确写「这是新朋友，记忆库还没有小忆的记录」 |

## 重置与重复执行

- 记忆写入是追加式的，重复执行样例只会多一条记录，不影响判定；
- 需要干净环境：用 `scripts/init-scope.py` 的 `--seed` 与不同 `--url` 组合创建新 Scope，
  并同步更新应用环境变量 `PC_SCOPE_ID`（幂等键 `pet-with-memory-dify` 固定，同 key 复跑返回同一 Scope）；
- Dify 侧无需复位：会话与 PowerContext 记忆相互独立，换 `USER` 亦不影响记忆 Scope。
