# StudyCoach 验证样例

两组可按步骤执行的样例。样例一走演示模式（无需部署），样例二连接真实 PowerContext
（核对记忆读写记录，满足"技术结合有效"的基础验收）。

---

## 样例一：演示模式（零依赖，2 分钟）

**初始数据**：无（内置演示记忆）。

**步骤**：
1. 打开项目网站（Qoder Sites 地址或本地 `site/index.html`）。右上角徽标为灰色「未连接 · 演示模式」。
2. 左侧「今日学习打卡」：
   - 学科/主题填 `高等数学 · 中值定理`
   - 没把握的薄弱点填两行：
     - `拉格朗日中值定理构造辅助函数的思路`
     - `柯西中值定理与拉格朗日的条件区别`
3. 点 **保存到记忆**：日志区出现两条 `✅（演示）[weakness] ...`。
4. 右侧「开始复习」输入 `复习中值定理，下周考试`，点 **生成复习清单**：
   - **预期**：「本次优先复习（历史薄弱点）」列出上面两条薄弱点 + 建议的复习路径。
5. 右下「记忆库一览」可看到薄弱/进展/偏好分类标签的条目。

**预期结果**：全流程可交互，薄弱点出现在复习清单首位。

## 样例二：连接 PowerContext（核对记忆读写）

**初始数据**：PowerContext 服务已启动（`http://127.0.0.1:8000`），适配器已启动
（`python scripts/adapter.py`，监听 `http://127.0.0.1:8787`）。

**步骤**：
1. 网页 ⚙ 设置：适配器地址 `http://127.0.0.1:8787`，Scope ID 填 `study-coach-validation`，
   点 **保存并测试连接**。**预期**：提示 ✅ 连接成功，右上角徽标变绿。
2. 打卡：主题 `数据结构 · 二叉树`，薄弱点一行 `AVL 树四种旋转的区分`，
   掌握内容 `会手写层序遍历`。点 **保存到记忆**。
   **预期**：日志显示两条 `✅ [weakness]/[progress] ...`（HTTP 201/200）。
3. **核对记忆写入记录**（任选其一）：
   - 网页「记忆库一览」点 **刷新**：出现刚写入的两条；
   - 直接调服务端接口核对：

     ```bash
     curl -s -X POST http://127.0.0.1:8000/v1/memory/entries/list \
       -H "Content-Type: application/json" \
       -d '{"scope_id":"study-coach-validation"}'
     ```

     预期返回 `entries` 中包含 `AVL 树四种旋转的区分`（kind=weakness）。
4. **跨会话复用验证**：关闭浏览器标签页，重新打开网页（或换浏览器），直接点「开始复习」
   输入 `复习二叉树的旋转`。
   **预期**：复习清单中召回 `AVL 树四种旋转的区分`——证明记忆持久化在 PowerContext
   服务端，而非浏览器本地。
5. （可选）第二次打卡确认该薄弱点已掌握后再次复习，观察召回内容随记忆更新的变化。

**预期结果汇总**：
| 验收点 | 结果 |
| --- | --- |
| 连接测试 | 设置保存后右上角绿色徽标 |
| 记忆写入 | `remember` 返回成功，`entries/list` 可查到新条目 |
| 记忆召回 | `prepare` 返回的 context 中包含历史薄弱点文本 |
| 跨会话持久 | 换浏览器/重开页面后仍能召回 |

## 常见问题

- **连接测试失败（CORS / 502）**：确认适配器已启动且地址填的是适配器（8787）而不是
  PowerContext（8000）；PowerContext 若开启鉴权，Token 需一并填入设置。
- **演示模式与真实模式数据不互通**：演示数据仅存于页面内存，连接服务后请用同一 Scope
  重新打卡。
